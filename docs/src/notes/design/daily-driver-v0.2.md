# v0.2「日常使い版」— 合格基準と作業計画

## 定義

1日の作業を loom だけで終えられ、事故が起きても作業を失わないこと。
下の8領域すべてで未達が 0 になったとき、v0.2 を「日常使い版」と呼ぶ。
見た目と発見しやすさの改善（[roadmap-v0.3-v0.5.md](roadmap-v0.3-v0.5.md)）はこの基準に含めない。

## 合格基準（v0.1.0 時点の判定）

| 領域 | 満たしていること | 未達 | WP |
|---|---|---|---|
| 起動と $EDITOR | git commit・rebase -i・crontab 型・`+N`・新規ファイル、SIGTERM 143 / SIGHUP 129 / C-z | — | — |
| データの安全 | その場上書き、事前バックアップ、改行・BOM・不正バイトの保持、外部変更検出 | 退避（`#file#`・`~/.loom/recovery/`）から作業を戻せない | WP1 |
| 手癖の編集 | Emacs 参照表の束縛 41 件 | `C-x C-b`・`C-x s`（参照表で `:pending`） | WP4 |
| | | `M-m`・`M-\`・`M-SPC`・`M-t`・`M-z`・`M-=` がない | WP5 |
| 移動と一覧 | isearch・occur・next-error・プロジェクト検索・ブックマーク | file-tree が画面より長いと選択が見えない | WP3 |
| 言語 | CL / Elisp / Nix / Web / Markdown / Org のインデント・コメント・括弧 | CL の複数行文字列と `#\| \|#` の色が崩れる | WP6 |
| LSP | 補完・定義・hover・参照・rename・format・診断件数 | サーバからの要求に一切応答しない | WP7 |
| 止まらない | 性能ゲート | `M-:` の暴走でエディタごと止まる | WP2 |
| 実機で確かめた | — | 手動チェック5行が未記入 | WP0 |

## 1日のシナリオ（受け入れ用の通し E2E）

作者の日常を12場面に並べたもの。v0.1.0 では8場面で止まる。
全 WP が終わったら、この12場面を1本の PTY シナリオにして `t/e2e/scenarios/` に置く
（新しい導線規則 **R9「1日」**）。場面ごとに画面とファイルのバイト列を観測する。

| 時刻 | 場面 | 操作 | v0.1.0 | WP |
|---|---|---|---|---|
| 09:00 | 前回の続きから始める | `loom` | 昨夜の SIGHUP で退避した変更が見つからない | WP1 |
| 09:05 | ファイルを探して開く | `C-x p f` | 通る | — |
| 09:10 | Lisp を書く | `RET` `TAB` `M-;` `C-→` | 通る | — |
| 09:15 | 長い docstring と `#\| \|#` を書く | — | 2行目以降の色が崩れる | WP6 |
| 09:20 | 字下げ先頭へ・空白を詰める | `M-m` `M-\` | 何も起きない | WP5 |
| 09:30 | 式を試す | `M-:` | ループする式でエディタごと止まる | WP2 |
| 10:00 | ツリーで深い階層を開く | `C-x d` `C-c n` | 選択が画面外に消える | WP3 |
| 10:30 | TypeScript で補完と定義ジャンプ | `M-x lsp-start` `C-M-i` `M-.` | サーバによっては初期化の途中で止まる | WP7 |
| 11:00 | 開いているバッファを見渡す | `C-x C-b` | 未割り当て | WP4 |
| 14:00 | コミットメッセージを書く | `git commit` → loom | 通る | — |
| 15:00 | 置換して確認する | `M-%` `y` `n` `!` | 通る | — |
| 18:00 | まとめて保存して終える | `C-x s` `C-x C-c` | `C-x s` がない | WP4 |

10:30 は擬似サーバだけでなく、実物の typescript-language-server と nixd で確かめる（FR-V04）。

## 作業パッケージと順番

| 波 | WP | 理由 |
|---|---|---|
| 第1波（並列可） | WP3, WP4, WP5, WP7 | 互いに独立。触るスライスが重ならない |
| 第2波 | WP1, WP6 | 状態を持つ変更。WP6 は性能ゲートを見ながら |
| 第3波 | WP2 | スレッドの規則（[decisions.md](decisions.md) の Q3）を決めてから |
| 並行 | WP0 | 作者の作業（実装なし） |

規模は S < M の相対値。WP3・WP5 が S、それ以外は M。

## v0.2 の合格ゲート

- `nix run .#e2e -- --require-path-coverage` で `missing_paths` が 0
- 1日のシナリオ（R9）が12場面すべて通る
- 性能ゲートと境界テストが緑のまま
- `docs/src/notes/daily-driver-checklist.md` の5行が記入済み
